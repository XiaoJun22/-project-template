# 项目目录结构说明

本文档定义电动工具/电机控制类硬件+固件项目的标准工程目录结构，适用于团队协作、多轮打样及后期追溯。

---

## 一、顶层目录总览

```
Project_Root/
├── 00_input/          # 输入资料(客户需求、参考设计、竞品资料)
├── 01_docs/           # 方案与规格文档
├── 02_hardware/       # 硬件设计
├── 03_software/       # 固件工程
├── 04_report/         # 测试/评审/验证报告
├── 05_output/         # 最终交付物
├── 06_management/     # 项目管理
└── README.md          # 目录说明与命名规范
```

---

## 二、各目录详细说明

### 00_input — 输入资料

存放项目启动阶段获取的**外部输入**资料，不做任何加工。

```
00_input/
├── 客户需求/
├── 参考设计/
└── 竞品资料/
```

> 与 `01_docs` 的区别：`00_input` 是"别人给的/收集来的"原始资料；`01_docs` 是"我们自己产出的"设计文档。

---

### 01_docs — 方案与规格文档

存放项目**设计阶段**产出的规格与方案类文档（做之前/做的过程中写的）。

```
01_docs/
├── 需求规格说明书.md
├── 系统方案设计.md
└── 接口定义文档.md
```

---

### 02_hardware — 硬件设计

```
02_hardware/
├── Schematic/          # 原理图
├── PCB/
├── BOM/
├── 结构_3D/
└── 认证资料/            # CE / FCC / UL 等
```

> 多轮打样建议按版本建子目录，见第三节命名规范。

---

### 03_software — 固件工程

固件工程内部采用分层架构，具体如下：

```
03_software/
├── User/                  # 应用层：主循环、顶层状态机
├── Drivers/                # BSP层：GPIO/PWM/ADC/I2C/按键/LED等外设驱动
│   └── Devices/             # I2C/SPI等总线上挂载的具体器件驱动
├── Signal/                 # 信号调理层：滤波、单位换算、校准
├── Control/                 # 控制逻辑层：恒流控制、保护、状态判断
├── Indicator/               # 状态指示层：LED显示策略
├── Params/                 # 全局参数配置
└── Test/                    # 单元测试/台架测试脚本
```

> 分层原则：BSP 只做寄存器级采集/输出，不含业务逻辑；Signal 层输出物理量；Control 层只消费物理量，不直接碰寄存器/ADC码值。方向单向：`User → Control → Signal → Drivers`。

---

### 04_report — 报告

按报告性质分类，避免与 `01_docs` 混淆（`01_docs` 是设计输出，`04_report` 是验证结果）。

```
04_report/
├── 测试报告/            # 台架测试、性能测试
├── 评审报告/            # 设计评审(DR)、代码评审
└── 验证报告/            # EVT / DVT / PVT 阶段报告
```

---

### 05_output — 最终交付物

```
05_output/
├── 固件_bin/            # 带版本号命名的可烧录文件
├── 量产资料/            # 产线烧录文件、产测规范
└── 用户手册/
```

---

### 06_management — 项目管理

硬件类项目中常被忽略，但对进度跟踪和变更追溯非常重要，建议单独建目录。

```
06_management/
├── 项目计划.md
├── 风险登记表.md
└── 变更记录_ECN/        # 设计变更追踪(Engineering Change Notice)
```

---

## 三、命名规范

### 1. 版本号与日期命名

适用于 `02_hardware`（多轮PCB打样）和 `05_output`（多版本固件）等经常迭代的目录，统一格式：

```
Vx.x_YYYYMMDD
```

示例：
```
02_hardware/PCB/V1.0_20260310/
02_hardware/PCB/V1.1_20260405/
05_output/固件_bin/V2.3_20260710_release.bin
```

> 禁止使用"最终版"、"真的最终版"、"v2_确认版"等非规范命名。

### 2. 目录职责边界

| 目录 | 边界说明 |
|---|---|
| `00_input` | 只读，外部提供，不修改、不加工 |
| `01_docs` | 我方产出的设计/规格文档，做之前或做的过程中产生 |
| `04_report` | 验证结果类报告，做完之后测出来的数据/结论 |

---

## 四、团队协作建议

1. 根目录放置本说明文档（或简化版 `README.md`），新成员接手项目可快速了解目录用途与命名规则。
2. `06_management/变更记录_ECN` 需在每次硬件/固件重大变更后及时更新，便于追溯问题版本。
3. `03_software` 内部分层结构应作为固件工程模板固化到代码仓库脚手架中，新建项目时直接复制该骨架。
